# 二、Python 一切皆对象（Everything Is an Object）

这是理解 Python 内存管理的第一步。

在 Python 中，整数、字符串、列表、字典、函数、类，甚至类本身，都是对象。

例如：

```
number = 100name = "Agent"items = [1, 2, 3]def hello():    print("Hello Agent")class Agent:    pass
```

这里：

- `100` 是整数对象。
- `"Agent"` 是字符串对象。
- `[1, 2, 3]` 是列表对象。
- `hello` 是函数对象。
- `Agent` 是类对象。

与 C++ 不同，Python 的变量不直接表现为一个固定类型的存储容器，而是一个指向对象的引用。

这是一个非常重要的区别。

## 2.1 变量和对象是什么关系？

先看一段代码：

```
a = 100b = a
```

很多初学者会认为：

- `a` 保存一个整数 100。
- `b` 又保存一个整数 100。

但从 Python 对象模型来看，正确理解是：

- Python 创建或取得一个整数对象。
- `a` 指向这个对象。
- `b` 也指向同一个对象。

输出示例：

```

```

注意：上面的 `id()` 数值只是示意，不同 Python 运行环境可能不同。

其中：

```

```

表示判断两个变量是否引用同一个对象。

而：

```
a == b
```

表示判断两个对象的值是否相等。

这是两个完全不同的概念。

## 2.2 Identity、Type、Value

Python 对象具有三个核心属性。

| 属性       | 含义   | 对应操作     |
| -------- | ---- | -------- |
| Identity | 对象身份 | `id()`   |
| Type     | 对象类型 | `type()` |
| Value    | 对象的值 | 根据对象内容获取 |

例如：

```
name = "LangGraph"print(id(name))print(type(name))print(name)
```

输出：

```
某个对象的身份标识
<class 'str'>
LangGraph
```

理解这三个属性非常重要。

例如：

```
a = [1, 2, 3]b = a
```

此时：

- `a` 和 `b` 的 Identity 相同。
- `a` 和 `b` 的 Type 都是 `list`。
- 它们所引用的 Value 是同一个列表内容。

需要记住：变量名不是对象，对象才是真正存储数据的实体。

# 三、变量赋值与引用机制

这一部分是面试高频考点。

## 3.1 普通赋值

```
a = [1, 2, 3]b = ab.append(4)print(a)print(b)
```

输出：

```
[1, 2, 3, 4]
[1, 2, 3, 4]
```

为什么修改 `b`，`a` 也发生了变化？

因为：

```
b = a
```

并没有创建一个新列表，而是让 `b` 引用 `a` 所引用的列表对象。

所以修改 `b` 所指向的列表，也就是修改了 `a` 所指向的同一个列表。

## 3.2 变量重新赋值

再看：

```
a = [1, 2, 3]b = ab = [4, 5, 6]print(a)print(b)
```

输出：

```
[1, 2, 3]
[4, 5, 6]
```

这里的过程是：

1. `a` 引用列表对象 A。
2. `b = a`，`b` 也引用列表对象 A。
3. `b = [4, 5, 6]`，创建列表对象 B。
4. `b` 改为引用列表对象 B。
5. `a` 仍然引用列表对象 A。

注意：重新赋值并不会修改原对象，而是改变变量的引用关系。

## 3.3 `is` 和 `==` 的区别

这是 Python 面试中的经典问题。

```
a = [1, 2, 3]b = [1, 2, 3]print(a == b)print(a is b)
```

输出：

```
True
False
```

解释：

- `a == b`：两个列表的内容相同。
- `a is b`：两个列表不是同一个对象。

再看：

```
a = [1, 2, 3]b = aprint(a == b)print(a is b)
```

输出：

```
True
True
```

实际开发中：

- 判断数据内容是否相等，使用 `==`。
- 判断对象是否为同一个对象，使用 `is`。
- 判断是否为 None，使用 `is None`，不要使用 `== None`。

# 四、可变对象与不可变对象

这是 Python 对象模型中最重要的概念之一。

## 4.1 什么是可变对象？

可变对象（Mutable Object）是指对象创建后，可以在不改变对象身份的情况下修改其内部内容。

常见可变对象：

| 类型        | 示例                  |
| --------- | ------------------- |
| list      | `[1, 2, 3]`         |
| dict      | `{"name": "Agent"}` |
| set       | `{1, 2, 3}`         |
| bytearray | `bytearray(b"abc")` |
| 自定义类实例    | 普通可修改属性的实例          |

例如：

```
items = [1, 2, 3]old_id = id(items)items.append(4)new_id = id(items)print(items)print(old_id == new_id)
```

输出：

```
[1, 2, 3, 4]
True
```

说明列表内部数据发生了变化，但对象身份没有改变。

## 4.2 什么是不可变对象？

不可变对象（Immutable Object）是指对象创建后，其自身的值不能被原地修改。

常见类型：

| 类型        | 示例                  |
| --------- | ------------------- |
| int       | `100`               |
| float     | `3.14`              |
| bool      | `True`              |
| str       | `"Agent"`           |
| tuple     | `(1, 2, 3)`         |
| frozenset | `frozenset({1, 2})` |
| bytes     | `b"hello"`          |

例如：

```
name = "Agent"print(id(name))name = name + " Engineer"print(name)print(id(name))
```

这里并不是修改原来的字符串，而是创建了一个新字符串对象，然后让 `name` 引用新对象。

注意：不可变容器不代表其中所有元素都不可变。例如：

```
data = ([1, 2], 3)data[0].append(100)print(data)
```

输出：

```
([1, 2, 100], 3)
```

元组本身不可变，但它引用的列表仍然可以修改。

## 4.3 可变与不可变的核心区别

可变对象

列表对象

原对象\
`[1, 2, 3]`

同一对象\
`[1, 2, 3, 4]`

原地修改内容，对象身份保持不变。

不可变对象

字符串对象

原对象\
`"Agent"`

新对象\
`"Agent AI"`

创建新值并重新绑定变量，原字符串不变。

# 五、Python 引用计数机制（Reference Counting）

理解了对象引用之后，我们进一步研究 Python 如何知道一个对象是否还需要保留。

Python 内存管理的一个重要机制就是引用计数。

## 5.1 什么是引用计数？

引用计数（Reference Counting）是指：Python 通过记录一个对象被多少个地方引用，来判断该对象是否还在被使用。

当一个对象的引用数量增加时，引用计数通常增加。

当一个对象的引用数量减少时，引用计数通常减少。

当引用计数变为 0 时，该对象就不再有任何有效引用，在 CPython 中通常会立即释放对象。

看一个例子：

```
import sysa = [1, 2, 3]print(sys.getrefcount(a))b = aprint(sys.getrefcount(a))c = aprint(sys.getrefcount(a))del bprint(sys.getrefcount(a))del cprint(sys.getrefcount(a))
```

在常见的 CPython 环境中，输出通常是：

```
2
3
4
3
2
```

为什么第一次输出是 2，而不是 1？

因为：

```
sys.getrefcount(a)
```

调用 `getrefcount()` 时，会临时创建一个对对象的引用，用于传递参数。

因此：

- `a` 本身有一个引用。
- `getrefcount()` 的参数传递通常额外产生一个临时引用。

所以显示为 2。

不同 Python 实现和具体执行环境可能存在差异，不要把这些数字当成固定值。

## 5.2 哪些操作会增加引用计数？

常见情况：

```
a = [1, 2, 3]# 新增一个引用b = a# 容器保存对象引用container = [a]# 字典保存对象引用mapping = {"data": a}
```

这些操作都会让列表对象获得新的引用。

## 5.3 哪些操作会减少引用计数？

```
a = [1, 2, 3]b = a# 删除变量引用del b# 删除容器中的引用container = [a]del container# 变量重新绑定a = [4, 5, 6]
```

需要注意：

`del a` 删除的是变量名与对象之间的绑定关系，不是直接命令 Python 释放对象。

例如：

```
a = [1, 2, 3]b = adel aprint(b)
```

输出：

```
[1, 2, 3]
```

原因是对象仍然被 `b` 引用，因此不会因为删除 `a` 就被销毁。

## 5.4 引用计数与对象生命周期

我们通过一个完整的例子观察对象的生命周期。

```
import sysdef show_ref_count(name, obj):    print(        f"{name}: "        f"ref_count={sys.getrefcount(obj)}"    )data = [10, 20, 30]show_ref_count("初始状态", data)other = datashow_ref_count("新增引用", data)del othershow_ref_count("删除引用", data)del dataprint("data 已经删除")
```

核心过程：

对象生命周期

1. 创建对象

   `data = [10, 20, 30]`

   创建列表对象，并建立变量引用。
2. 增加引用

   `other = data`

   两个变量引用同一个对象。
3. 减少引用

   `del other`

   删除一个引用，`data` 仍然有效。
4. 引用归零

   `del data`

   在没有其他引用的情况下，列表对象可以被回收。

注意一个容易被忽视的问题：

Python 语言规范并不保证所有 Python 实现都采用 CPython 的引用计数实现。引用计数为 0 后立即释放，是 CPython 的典型行为，而不是所有 Python 实现必须遵守的规则。

# 六、Python 垃圾回收机制（Garbage Collection）

引用计数有一个明显缺陷：

它无法单独解决循环引用问题。

这也是 CPython 引入循环垃圾回收机制的重要原因。

## 6.1 什么是循环引用？

先看下面的代码：

```
class Node:    def __init__(self, name):        self.name = name        self.ref = Nonea = Node("A")b = Node("B")a.ref = bb.ref = a
```

现在形成了这样的关系：

### 循环引用结构

Node A

ref → B

Node B

ref → A

A 和 B 互相引用，形成闭环

现在删除外部引用：

```
del adel b
```

从程序逻辑上看，已经没有办法通过变量访问这两个对象了。

但对象内部仍然互相引用。

所以它们的引用计数可能都不为 0。

这就是循环引用导致的问题。

## 6.2 CPython 如何解决循环引用？

CPython 使用两套互相配合的机制：

1. 引用计数：处理绝大多数普通对象生命周期。
2. 循环垃圾回收器：检测特定可跟踪对象之间不可达的引用环。

循环垃圾回收器会识别容器对象之间的引用关系，判断哪些对象虽然互相引用，但已经无法从程序的外部可达路径访问。

符合回收条件后，就可以清理这些循环引用。

## 6.3 使用 gc 模块

Python 提供了 `gc` 模块，用于管理和调试垃圾回收。

```
import gc# 查看垃圾回收器是否启用print(gc.isenabled())# 查看当前垃圾回收统计print(gc.get_stats())# 手动执行垃圾回收collected = gc.collect()print("回收对象数量:", collected)# 查看垃圾回收阈值print(gc.get_threshold())# 查看当前各代对象数量print(gc.get_count())
```

注意：

`gc.collect()` 返回的是本次回收过程中收集的对象数量，不是释放的内存字节数。

## 6.4 循环引用完整测试

```
import gcimport weakrefclass Node:    def __init__(self, name):        self.name = name        self.ref = None# 确保自动垃圾回收已开启gc.enable()a = Node("A")b = Node("B")a.ref = bb.ref = a# 创建弱引用，不增加目标对象的强引用计数weak_a = weakref.ref(a)weak_b = weakref.ref(b)print("创建对象:", weak_a() is not None)print("创建对象:", weak_b() is not None)# 删除外部引用del adel b# 此时循环可能仍然存在print("回收前 A:", weak_a() is not None)# 手动触发垃圾回收gc.collect()print("回收后 A:", weak_a())print("回收后 B:", weak_b())
```

在正常的 CPython 环境下，预期结果是：

```
创建对象: True
创建对象: True
回收前 A: True
回收后 A: None
回收后 B: None
```

这里使用了一个新的概念：`weakref`。

弱引用不会像普通强引用一样增加目标对象的引用计数，因此可以用于观察对象是否还存活，而不会阻止其回收。

面试重点：引用计数负责快速处理普通对象回收，循环 GC 负责处理引用环。两者不是互相替代，而是协同工作。

# 七、CPython 内存分配机制

## 7.1 Python 内存管理结构

CPython 并不是每次创建一个 Python 对象，都直接向操作系统申请一块独立内存。

它有自己的内存分配器。

可以将其理解为以下结构：

Python 对象

CPython 内存管理层

对象分配与内存管理 API

适合小内存块的分配器

底层系统内存分配器

向操作系统申请和管理内存

这里需要认识三个术语。

### ① pymalloc

CPython 的专用小对象内存分配器。

在 CPython 3.11 中，它主要用于管理不超过 512 字节的小内存请求。

它通过更大的内存区域进行组织和分配，减少频繁调用底层系统分配器的开销。

### ② Arena

Arena 是 pymalloc 用于管理内存的较大区域。

在常见的 64 位 CPython 3.11 构建中，一个 Arena 通常是 256 KiB。

Arena 进一步划分为多个 Pool。

### ③ Pool

Pool 是 Arena 中用于管理相同大小类别内存块的区域。

在常见的 64 位 CPython 3.11 中，Pool 通常是 4 KiB。

Pool 再划分成多个 Block，用于分配具体的小对象内存请求。

## 7.2 为什么 Python 删除对象后，进程内存不一定下降？

这是非常重要的工程问题。

例如：

```
import sysdata = []for i in range(1_000_000):    data.append(i)print("列表长度:", len(data))del data
```

你可能会发现：

虽然 `data` 已经删除，但操作系统任务管理器中显示的 Python 进程内存并没有明显下降。

为什么？

因为：

- Python 对象已经可能被释放。
- pymalloc 可能保留已经释放的内存块，以便后续重新使用。
- 底层分配器可能保留内存区域。
- 操作系统不一定立即回收这些内存页。

所以需要区分三个概念：

| 概念     | 含义              |
| ------ | --------------- |
| 对象释放   | 对象不再有效，可以被销毁    |
| 内存块释放  | 分配器可以重新利用内存     |
| 进程内存下降 | 操作系统实际看到的进程占用减少 |

这三个动作并不一定同时发生。

## 7.3 使用 sys.getsizeof() 查看对象大小

Python 提供了：

```
import sysnumber = 100name = "Agent"items = [1, 2, 3]print(sys.getsizeof(number))print(sys.getsizeof(name))print(sys.getsizeof(items))
```

`sys.getsizeof()` 返回的是对象自身的浅层大小。

例如：

```
import sysdata = [[1, 2, 3], [4, 5, 6]]print(sys.getsizeof(data))print(sys.getsizeof(data[0]))
```

第一行不会递归计算内部两个列表的全部大小。

因此，分析复杂对象的内存占用时，不能简单地将 `getsizeof()` 用在最外层对象上就得出完整结论。

# 八、Python 内存泄漏及其排查

这是从 Python 基础走向后端工程开发必须掌握的知识。

## 8.1 什么是内存泄漏？

内存泄漏（Memory Leak）是指：

程序已经不再需要某些对象，但由于仍然存在不必要的引用，导致这些对象无法被释放，内存占用持续增长。

例如：

```
cache = []def process_request(data):    cache.append(data)
```

每次请求都会将数据加入 `cache`，但是程序从来没有删除旧数据。

如果这是一个长期运行的 Agent 服务，随着请求数量增长，内存占用就可能越来越大。

## 8.2 Agent 服务中常见的内存泄漏场景

| 场景          | 可能的问题       | 解决方案         |
| ----------- | ----------- | ------------ |
| 对话历史        | 消息无限累积      | 限制历史长度、摘要压缩  |
| 全局缓存        | 缓存无限增长      | LRU、TTL、容量限制 |
| Agent State | 不必要的数据长期保留  | 状态清理         |
| 工具执行结果      | 保存大量原始结果    | 结果裁剪、持久化     |
| 任务队列        | 任务不断堆积      | 背压、限流        |
| 循环引用        | 对象引用环无法及时清理 | 正确管理生命周期     |
| 回调函数        | 闭包长期持有对象    | 解除注册、弱引用     |

这里特别注意：Agent 的对话历史增长不一定属于严格意义上的内存泄漏。如果程序有意保存历史消息，那属于内存使用持续增长，需要通过容量控制解决。

## 8.3 实战一：解决无限增长的对话历史

先看错误写法：

```
class ConversationManager:    def __init__(self):        self.messages = []    def add_message(self, message):        self.messages.append(message)    def get_messages(self):        return self.messagesmanager = ConversationManager()for i in range(100000):    manager.add_message({        "role": "user",        "content": f"message-{i}"    })print(len(manager.get_messages()))
```

问题：

- 消息数量无限增长。
- 历史消息越来越多。
- 每次构建 Prompt 都需要处理更多内容。
- Token 消耗不断增加。
- 内存占用也会持续增长。

改进方案：

```
from collections import dequefrom typing import Dict, Listclass ConversationManager:    def __init__(self, max_messages: int = 100):        self.messages = deque(maxlen=max_messages)    def add_message(self, message: Dict[str, str]) -> None:        self.messages.append(message)    def get_messages(self) -> List[Dict[str, str]]:        return list(self.messages)    def clear(self) -> None:        self.messages.clear()if __name__ == "__main__":    manager = ConversationManager(max_messages=100)    for i in range(100000):        manager.add_message({            "role": "user",            "content": f"message-{i}"        })    messages = manager.get_messages()    print("当前消息数量:", len(messages))    print("第一条消息:", messages[0])    print("最后一条消息:", messages[-1])
```

输出：

```
当前消息数量: 100
第一条消息: {'role': 'user', 'content': 'message-99900'}
最后一条消息: {'role': 'user', 'content': 'message-99999'}
```

这里使用了：

```
deque(maxlen=100)
```

它会自动限制容器最多保存 100 条消息。

但是在实际 Agent 系统中，不能简单地直接丢弃最早的消息。

更合理的方式是：

1. 保留 System Prompt。
2. 保留最近的若干轮对话。
3. 将较早对话压缩为摘要。
4. 必要时从长期记忆中检索历史信息。

这部分会在第 11 章和第 20 章深入实现。

## 8.4 实战二：使用 tracemalloc 排查内存增长

Python 提供 `tracemalloc`，可以追踪 Python 内存分配情况。

先看一个完整示例：


这段代码做了什么？

| 操作                    | 作用       |
| --------------------- | -------- |
| `tracemalloc.start()` | 开启内存分配追踪 |
| `take_snapshot()`     | 获取内存快照   |

## 8.5 实战三：使用 weakref 避免不必要的强引用

在一些缓存或对象管理场景中，弱引用可以避免管理器长期持有对象。

例如：

```
import weakrefclass Agent:    def __init__(self, name):        self.name = nameagent = Agent("ResearchAgent")# 创建弱引用agent_ref = weakref.ref(agent)print(agent_ref().name)# 删除强引用del agent# 目标对象被销毁后，弱引用返回 Noneprint(agent_ref())
```

输出：

```
ResearchAgent
None
```

弱引用适用于：

- 对象注册表。
- 观察者模式。
- 缓存管理。
- 对象生命周期监控。

但不要误以为所有缓存都应该使用弱引用。弱引用不会保证对象持续存在，如果没有其他强引用，对象可能随时被回收。

# 九、结合 AI Agent 工程理解对象模型

现在将前面的 Python 原理应用到实际 Agent 项目。

## 9.1 为什么 Agent State 容易出现引用问题？

假设有两个 Agent 节点：

- Research Agent：负责研究。
- Summary Agent：负责总结。

它们共享一个状态对象：

```
state = {    "messages": [],    "research_results": [],    "summary": ""}
```

如果两个节点直接修改同一个列表，就可能出现意料之外的状态变化。

例如：

```
def research_node(state):    state["research_results"].append(        "Research result A"    )    return statedef summary_node(state):    state["research_results"].clear()    state["summary"] = "Research completed"    return statestate = {    "research_results": [],    "summary": ""}research_node(state)print("研究结果:", state["research_results"])summary_node(state)print("研究结果:", state["research_results"])
```

输出：

```
研究结果: ['Research result A']
研究结果: []
```

Summary 节点本来可能只想处理摘要，但它意外地清空了共享状态中的研究结果。

这就是可变对象共享带来的副作用。

## 9.2 改进：避免直接修改共享状态

可以采用复制和返回更新的方式：

```
from copy import deepcopyfrom typing import Any, Dictdef research_node(state: Dict[str, Any]):    new_results = list(state["research_results"])    new_results.append("Research result A")    return {        "research_results": new_results    }def summary_node(state: Dict[str, Any]):    # 读取数据，但不修改原列表    results = list(state["research_results"])    summary = (        f"共获得 {len(results)} 条研究结果"    )    return {        "summary": summary    }state = {    "research_results": [],    "summary": ""}research_update = research_node(state)state.update(research_update)summary_update = summary_node(state)state.update(summary_update)print(state)
```

输出：

```
{
    'research_results': ['Research result A'],
    'summary': '共获得 1 条研究结果'
}
```

这里体现了一种非常重要的工程思想：

尽量避免多个模块直接修改同一个可变对象，优先通过明确的输入、输出和状态更新机制协作。

不过，`state.update()` 本身也是原地修改字典。生产环境中还需要根据并发执行模型、状态所有权和框架的 Reducer 语义进行设计。

在 LangGraph 中，节点通常返回状态更新，由 Graph 根据 State Schema 和 Reducer 规则合并更新，并不是简单地将整个状态随意共享给多个节点修改。

这也正是后续第 24 章需要深入研究的核心内容。

## 9.3 Agent 工程中对象管理的建议

| 场景          | 建议             |
| ----------- | -------------- |
| Agent State | 明确状态所有权和更新规则   |
| 消息历史        | 使用有界缓存与摘要      |
| 工具参数        | 使用 Pydantic 校验 |
| 工具返回值       | 避免共享可变对象       |
| 并发节点        | 避免无保护的共享状态修改   |
| 长期记忆        | 使用数据库持久化       |
| 临时对象        | 明确生命周期         |
| 大型数据        | 避免不必要的深拷贝      |

特别提醒：不要为了避免引用问题而对所有数据都使用 `deepcopy()`。对于包含大型列表、模型数据或复杂对象的状态，深拷贝可能造成显著的内存和性能开销。

## Python 对象模型与内存管理知识体系

1. 对象模型

   Python 中变量名引用对象，对象具有 Identity、Type、Value。
2. 引用机制

   使用 `gc`、`weakref`、`tracemalloc` 等工具。

   通过明确状态所有权、控制缓存大小和避免共享可变状态，提升系统稳定性。
