# 1.4 Python 装饰器与闭包机制

这一节是 Python 高级编程中非常重要的内容，也是 AI Agent 工程师面试的高频考点。

在实际 Agent 项目中，你会经常看到类似的代码：

```
@tooldef search_web(query: str):    """搜索互联网。"""    return "搜索结果"@retry(max_attempts=3)def call_llm():    pass@log_executiondef execute_agent():    pass
```

这些 `@xxx` 就是装饰器（Decorator）。

装饰器广泛应用于：

- LangChain Tool 定义与工具增强。
- Agent 执行日志与调用追踪。
- API 鉴权与权限控制。
- LLM 请求重试与超时控制。
- 函数执行时间统计。
- 缓存、限流和并发控制。
- Agent 中间件和生命周期管理。

本节不只是讲如何使用 `@`，还要从 Python 的函数对象、作用域、闭包和高阶函数开始，理解装饰器的底层执行机制。

## 1.4.1 Python 函数对象与高阶函数

理解装饰器之前，必须先理解一个概念：

Python 中的函数本身也是对象。

### 1. 函数可以赋值给变量

```
def say_hello():    print("Hello Python")func = say_hellofunc()
```

输出：

```
Hello Python
```

这里：

```
func = say_hello
```

并没有执行函数。

它只是让变量 `func` 引用与 `say_hello` 相同的函数对象。

验证：

```
def say_hello():    print("Hello")func = say_helloprint(func is say_hello)print(type(func))print(id(func) == id(say_hello))
```

输出：

```
True
<class 'function'>
True
```

这说明：

- 函数可以赋值。
- 函数可以通过变量调用。
- 函数具有对象身份。
- 函数可以作为参数传递。
- 函数可以作为返回值。

这就是装饰器设计的基础。

### 2. 函数可以作为参数传递

例如：

```
def say_hello():    print("Hello")def execute(func):    print("准备执行函数")    func()    print("函数执行完成")execute(say_hello)
```

输出：

```
准备执行函数
Hello
函数执行完成
```

这里：

```
execute(say_hello)
```

将函数对象传递给另一个函数。

这种将函数作为参数传递的函数，通常称为高阶函数（Higher-Order Function）。

### 3. 函数可以作为返回值

```
def outer():    def inner():        print("执行 inner")    return innerfunc = outer()func()
```

输出：

```
执行 inner
```

这里：

```
return inner
```

返回的是函数对象，而不是函数执行结果。

这与下面的写法完全不同：

```
def outer():    def inner():        print("执行 inner")    return inner()func = outer()
```

第二种写法返回的是 `inner()` 的执行结果。

如果 `inner()` 没有显式返回值，那么 `func` 就是 `None`。

这是装饰器初学者最容易犯的错误之一。

### 4. Python 函数对象的常用属性

```
def calculate(a, b):    """计算两个数字之和。"""    return a + bprint(calculate.__name__)print(calculate.__doc__)print(calculate.__module__)print(calculate.__defaults__)
```

输出：

```
calculate
计算两个数字之和。
__main__
None
```

函数对象还可以动态添加属性：

```
def execute():    passexecute.description = "执行 Agent 任务"execute.version = "1.0"print(execute.description)print(execute.version)
```

这在框架开发中很有用，例如给工具函数附加元数据。

### 5. 高阶函数的实际应用

假设我们需要对 Agent 函数执行前后的行为进行统一控制。

```
def execute_with_logging(func):    print("开始执行:", func.__name__)    result = func()    print("执行结束:", func.__name__)    return resultdef run_agent():    print("Agent 正在执行")    return "Agent Result"result = execute_with_logging(run_agent)print(result)
```

输出：

```
开始执行: run_agent
Agent 正在执行
执行结束: run_agent
Agent Result
```

这种设计已经具备装饰器的基本思想。

但每次调用都需要写：

```
execute_with_logging(run_agent)
```

不够方便。

装饰器可以将这种增强逻辑封装起来。

## 1.4.2 闭包（Closure）机制

闭包是理解装饰器的核心。

如果不了解闭包，就很难真正理解装饰器为什么能够记住外部函数的变量。

### 1. 什么是闭包？

先看代码：

```
def outer():    message = "Hello Python"    def inner():        print(message)    return innerfunc = outer()func()
```

输出：

```
Hello Python
```

这里发生了什么？

正常情况下：

```
def outer():    message = "Hello Python"
```

当 `outer()` 执行结束后，它的局部作用域通常就不再通过普通函数调用栈维持。

但是：

```
return inner
```

将内部函数返回了出去。

而内部函数仍然需要访问：

```
message
```

因此，Python 会保留内部函数所需的外部作用域绑定。

这种机制就是闭包。

闭包通常由三个条件组成：

1. 存在嵌套函数。
2. 内部函数引用了外部函数的变量。
3. 外部函数返回内部函数，使内部函数能够在外部函数执行结束后继续使用这些变量。

### 2. 查看闭包变量

Python 可以通过：

```
function.__closure__
```

查看闭包单元。

示例：

```
def outer():    message = "Hello Closure"    def inner():        print(message)    return innerfunc = outer()print(func.__closure__)
```

输出类似：

```
(<cell at 0x...: str object at 0x...>,)
```

继续查看：

```
print(func.__closure__[0].cell_contents)
```

输出：

```
Hello Closure
```

还可以使用：

```
print(func.__code__.co_freevars)
```

输出：

```
('message',)
```

`co_freevars` 表示函数引用的自由变量名称。

### 3. 闭包如何保留状态？

看一个计数器：

```
def create_counter():    count = 0    def counter():        nonlocal count        count += 1        return count    return countercounter = create_counter()print(counter())print(counter())print(counter())
```

输出：

```
1
2
3
```

这里需要重点理解：

```
nonlocal count
```

它表示修改外层函数作用域中的 `count`，而不是创建一个新的局部变量。

如果没有 `nonlocal`：

```
def create_counter():    count = 0    def counter():        count += 1        return count    return counter
```

调用时会报错：

```
UnboundLocalError
```

因为 Python 会将函数内部赋值的 `count` 视为局部变量，而在执行 `count += 1` 时，局部变量还没有初始化。

### 4. global、nonlocal 与局部变量的区别

| 关键字        | 作用域  | 作用           |
| ---------- | ---- | ------------ |
| 普通变量       | 当前函数 | 创建局部变量       |
| `global`   | 模块级  | 修改模块全局变量     |
| `nonlocal` | 外层函数 | 修改最近一层外部函数变量 |

示例：

```
count = 100def outer():    count = 10    def inner():        nonlocal count        count += 1        print("inner:", count)    inner()    print("outer:", count)outer()print("global:", count)
```

输出：

```
inner: 11
outer: 11
global: 100
```

### 5. 多层闭包

```
def level_one():    a = "A"    def level_two():        b = "B"        def level_three():            print(a, b)        return level_three    return level_twofunc = level_one()()func()
```

输出：

```
A B
```

`level_three` 同时引用了两层外部作用域中的变量。

可以查看：

```
print(func.__code__.co_freevars)for cell in func.__closure__:    print(cell.cell_contents)
```

这说明闭包不仅可以保留一层外部变量，也可以引用多层外部作用域。

### 6. 闭包的工程应用：配置封装

例如，我们需要创建多个不同配置的 Agent 执行函数。

```
def create_agent(model_name, temperature):    def run(prompt):        print("模型:", model_name)        print("温度:", temperature)        print("Prompt:", prompt)    return runagent_a = create_agent(    "deepseek-chat",    0.0)agent_b = create_agent(    "gpt-model",    0.7)agent_a("分析 Python 生成器")agent_b("编写一个故事")
```

输出：

```
模型: deepseek-chat
温度: 0.0
Prompt: 分析 Python 生成器

模型: gpt-model
温度: 0.7
Prompt: 编写一个故事
```

两个函数拥有各自独立的闭包状态。

这种方式可以用于创建具有独立配置的处理函数。

不过，真正的 Agent 工程中，复杂配置通常更适合使用配置对象、依赖注入或类来管理，而不是将所有状态都隐藏在闭包中。

## 1.4.3 从高阶函数到装饰器

现在已经掌握：

- 函数可以作为参数。
- 函数可以作为返回值。
- 内部函数可以引用外部变量。
- 闭包可以保留外部作用域。

接下来正式实现装饰器。

### 1. 不使用装饰器实现功能增强

假设有一个 Agent：

```
def run_agent():    print("Agent 执行中")    return "执行结果"
```

现在希望增加日志功能。

可以写：

```
def log_execution(func):    def wrapper():        print("执行开始")        result = func()        print("执行结束")        return result    return wrapper
```

使用：

```
def run_agent():    print("Agent 执行中")    return "执行结果"run_agent = log_execution(run_agent)result = run_agent()print(result)
```

输出：

```
执行开始
Agent 执行中
执行结束
执行结果
```

这一行是关键：

```
run_agent = log_execution(run_agent)
```

执行过程：

1. 将原始 `run_agent` 函数传入 `log_execution`。
2. `log_execution` 创建内部函数 `wrapper`。
3. 返回 `wrapper`。
4. 将原来的 `run_agent` 名称重新绑定到 `wrapper`。
5. 此后调用 `run_agent()`，实际执行的是 `wrapper()`。

这就是装饰器的核心原理。

### 2. 使用 @ 语法糖

上面的代码可以改写成：

```
def log_execution(func):    def wrapper():        print("执行开始")        result = func()        print("执行结束")        return result    return wrapper@log_executiondef run_agent():    print("Agent 执行中")    return "执行结果"result = run_agent()print(result)
```

两者完全等价：

```
@log_executiondef run_agent():    pass
```

相当于：

```
def run_agent():    passrun_agent = log_execution(run_agent)
```

注意：

装饰器表达式在函数定义时执行，而不是每次调用被装饰函数时重新执行。

### 3. 装饰器的执行时机

```
def decorator(func):    print("装饰器执行")    def wrapper():        print("wrapper 执行")        return func()    return wrapper@decoratordef test():    print("test 执行")print("程序开始")test()
```

输出：

```
装饰器执行
程序开始
wrapper 执行
test 执行
```

这里说明：

- 模块加载、执行函数定义时，装饰器先执行。
- 调用 `test()` 时，才执行 `wrapper()`。
- 原始函数在 `wrapper()` 中被调用。

这也是为什么装饰器常用于启动阶段注册工具、路由或插件。

## 1.4.4 装饰器的参数传递与通用设计

刚才的装饰器存在一个问题：

```
def wrapper():    return func()
```

它只能装饰不需要参数的函数。

实际项目中的函数通常都有参数。

### 1. 使用固定参数

```
def log_execution(func):    def wrapper(name):        print("执行开始")        result = func(name)        print("执行结束")        return result    return wrapper@log_executiondef greet(name):    return f"Hello, {name}"print(greet("Alice"))
```

这个版本可以工作，但只能处理一个位置参数。

如果被装饰函数参数不同，就会出现问题。

### 2. 使用 \*args 和 \*\*kwargs

Python 装饰器通常使用：

```
*args**kwargs
```

实现通用参数传递。

```
def log_execution(func):    def wrapper(*args, **kwargs):        print("执行开始")        result = func(*args, **kwargs)        print("执行结束")        return result    return wrapper@log_executiondef add(a, b):    return a + b@log_executiondef greet(name, age=None):    return {        "name": name,        "age": age    }print(add(10, 20))print(    greet(        "Alice",        age=25    ))
```

输出：

```
执行开始
执行结束
30
执行开始
执行结束
{'name': 'Alice', 'age': 25}
```

这就是通用同步装饰器最常见的参数处理方式。

### 3. 为什么必须返回原始函数的结果？

看下面的错误实现：

```
def decorator(func):    def wrapper(*args, **kwargs):        func(*args, **kwargs)    return wrapper
```

它没有返回：

```
func(*args, **kwargs)
```

的执行结果。

所以：

```
@decoratordef add(a, b):    return a + bresult = add(10, 20)print(result)
```

最终输出：

```
None
```

正确实现：

```
def decorator(func):    def wrapper(*args, **kwargs):        result = func(*args, **kwargs)        return result    return wrapper
```

这条原则很重要：

装饰器应该正确保留被装饰函数的返回值，除非它明确要改变函数的返回语义。

### 4. 使用 functools.wraps 保留函数元数据

现在看一个容易被忽略的问题。

```
def decorator(func):    def wrapper(*args, **kwargs):        return func(*args, **kwargs)    return wrapper@decoratordef run_agent():    """执行 Agent。"""    passprint(run_agent.__name__)print(run_agent.__doc__)
```

输出：

```
wrapper
None
```

原始函数名称和文档字符串丢失了。

这是因为：

```
run_agent = decorator(run_agent)
```

重新绑定之后，`run_agent` 指向的是 `wrapper`。

### 正确方式：functools.wraps

```
from functools import wrapsdef decorator(func):    @wraps(func)    def wrapper(*args, **kwargs):        return func(*args, **kwargs)    return wrapper@decoratordef run_agent():    """执行 Agent。"""    passprint(run_agent.__name__)print(run_agent.__doc__)
```

输出：

```
run_agent
执行 Agent。
```

`@wraps(func)` 会复制原始函数的重要元数据，并设置 `__wrapped__`，方便调试、文档生成和部分反射工具获取原始函数信息。

例如：

```
print(run_agent.__wrapped__)
```

可以访问原始函数对象。

实际工程中，绝大多数自定义装饰器都应该使用 `functools.wraps`。

## 1.4.5 带参数的装饰器

前面已经实现了普通装饰器。

现在考虑一个需求：

希望指定重试次数。

例如：

```
@retry(max_attempts=3)def call_llm():    pass
```

这里的 `max_attempts=3` 就是装饰器参数。

它的实现方式与普通装饰器略有不同。

### 1. 三层函数结构

```
def retry(max_attempts):    def decorator(func):        def wrapper(*args, **kwargs):            for attempt in range(max_attempts):                try:                    return func(*args, **kwargs)                except Exception:                    if attempt == max_attempts - 1:                        raise        return wrapper    return decorator
```

使用：

```
@retry(max_attempts=3)def call_llm():    print("调用模型")    return "Success"print(call_llm())
```

输出：

```
调用模型
Success
```

这里有三个层次：

| 函数            | 作用        |
| ------------- | --------- |
| `retry()`     | 接收装饰器配置参数 |
| `decorator()` | 接收被装饰函数   |
| `wrapper()`   | 实际拦截函数调用  |

### 2. 执行过程

当 Python 执行：

```
@retry(max_attempts=3)def call_llm():    pass
```

可以理解为：

```
def call_llm():    passcall_llm = retry(max_attempts=3)(call_llm)
```

实际执行顺序：

```
retry(max_attempts=3)
        ↓
返回 decorator
        ↓
decorator(call_llm)
        ↓
返回 wrapper
        ↓
call_llm 重新绑定为 wrapper
```

注意：`max_attempts` 被 `decorator` 和 `wrapper` 通过闭包访问。

这就是闭包与装饰器结合的典型场景。

### 3. 实现一个完整的重试装饰器

接下来实现更接近工程项目的版本。

文件：

`chapter_01/section_1_4/retry_decorator.py`


这个示例展示了重试装饰器的基本结构。

不过，生产环境中还需要注意：

1. 不要对所有异常无差别重试。
2. 只对适合重试的暂时性错误重试。
3. 对有副作用的操作，需要考虑幂等性。
4. 可以使用指数退避（Exponential Backoff）。
5. 可以加入随机抖动（Jitter），避免大量请求同时重试。
6. 异步函数必须使用异步重试实现，不能直接在事件循环中调用 `time.sleep()`。

下一节还会实现异步装饰器。

## 1.4.6 多个装饰器的执行顺序

实际项目中，一个函数可能同时使用多个装饰器。

例如：

```
@decorator_a@decorator_bdef execute():    pass
```

它的执行顺序是什么？

### 1. 装饰器应用顺序

上面的代码等价于：

```
execute = decorator_a(    decorator_b(execute))
```

也就是：

从下往上应用装饰器。

### 2. 实际执行示例

```
from functools import wrapsdef decorator_a(func):    @wraps(func)    def wrapper(*args, **kwargs):        print("A 开始")        result = func(*args, **kwargs)        print("A 结束")        return result    return wrapperdef decorator_b(func):    @wraps(func)    def wrapper(*args, **kwargs):        print("B 开始")        result = func(*args, **kwargs)        print("B 结束")        return result    return wrapper@decorator_a@decorator_bdef execute():    print("执行原始函数")execute()
```

输出：

```
A 开始
B 开始
执行原始函数
B 结束
A 结束
```

可以理解为：

```
decorator_a
    |
    v
wrapper_a
    |
    v
decorator_b
    |
    v
wrapper_b
    |
    v
原始函数
```

### 3. 在 Agent 中的应用

例如：

```
@log_execution@retry(max_attempts=3)@measure_timedef call_llm():    pass
```

等价于：

```
call_llm = log_execution(    retry(max_attempts=3)(        measure_time(call_llm)    ))
```

装饰器的排列顺序会影响行为。

例如：

- 日志装饰器放在外层，可以记录整个重试过程。
- 计时装饰器放在内层，可以记录单次调用耗时。
- 计时装饰器放在外层，可以记录包括重试等待在内的总耗时。

这不是纯粹的语法问题，而是工程设计问题。

## 1.4.7 类装饰器与装饰器类

前面我们使用函数实现装饰器。

实际上，也可以使用类实现装饰器。

### 1. 类装饰器的基本形式

```
class LogDecorator:    def __init__(self, func):        self.func = func    def __call__(self, *args, **kwargs):        print("执行开始")        result = self.func(*args, **kwargs)        print("执行结束")        return result@LogDecoratordef execute():    print("执行 Agent")execute()
```

输出：

```
执行开始
执行 Agent
执行结束
```

这里：

```
@LogDecorator
```

等价于：

```
execute = LogDecorator(execute)
```

`LogDecorator` 创建了一个对象。

由于它实现了：

```
__call__()
```

因此对象可以像函数一样调用。

### 2. 函数装饰器与类装饰器的区别

| 对比     | 函数装饰器    | 类装饰器          |
| ------ | -------- | ------------- |
| 实现方式   | 闭包       | 类与 `__call__` |
| 状态保存   | 闭包变量     | 实例属性          |
| 实现复杂状态 | 相对不方便    | 更直观           |
| 生命周期管理 | 依赖闭包对象   | 依赖实例对象        |
| 常见用途   | 日志、计时、重试 | 有状态调用控制、注册器   |

### 3. 类装饰器保存调用状态

例如统计一个 Agent 函数被调用了多少次：

```
class CallCounter:    def __init__(self, func):        self.func = func        self.count = 0    def __call__(self, *args, **kwargs):        self.count += 1        print(            f"第 {self.count} 次调用"        )        return self.func(*args, **kwargs)@CallCounterdef execute_agent():    return "Agent Result"print(execute_agent())print(execute_agent())print(execute_agent())
```

输出：

```
第 1 次调用
Agent Result

第 2 次调用
Agent Result

第 3 次调用
Agent Result
```

这里的 `count` 保存在装饰器实例中。

### 4. 类装饰器的一个工程陷阱

如果使用类实例替换原始函数：

```
execute_agent = CallCounter(execute_agent)
```

那么 `execute_agent` 已经不再是原来的函数对象，而是 `CallCounter` 实例。

这可能影响：

- 函数签名反射。
- 类型检查。
- 框架扫描函数元数据。
- 某些依赖函数身份的工具。

所以需要根据具体框架决定是否采用类装饰器。

另外，普通类实例实现 `__call__` 并不自动意味着它支持 `inspect.signature()` 对原始函数签名的所有预期行为。需要时应明确处理元数据与签名。

## 1.4.8 装饰器在 Agent 工程中的实际应用

到这里，我们已经掌握了装饰器的基本原理。

现在将其应用到 Agent 系统中。

### 应用一：执行时间统计

Agent 中需要知道每个节点执行了多长时间。

实现：

`chapter_01/section_1_4/timing_decorator.py`

```
import timefrom functools import wrapsdef measure_time(func):    @wraps(func)    def wrapper(*args, **kwargs):        start = time.perf_counter()        try:            return func(*args, **kwargs)        finally:            elapsed = (                time.perf_counter() - start            )            print(                f"[Timing] {func.__name__}: "                f"{elapsed:.4f}s"            )    return wrapper@measure_timedef execute_agent():    time.sleep(1)    return "Agent 完成"if __name__ == "__main__":    result = execute_agent()    print(result)
```

这里使用：

```
time.perf_counter()
```

而不是 `time.time()`。

因为 `perf_counter()` 更适合测量短时间间隔。

另外，使用 `finally` 可以保证函数正常返回或者抛出异常时，都会执行耗时记录。

### 应用二：异常处理装饰器

```
from functools import wrapsdef handle_exception(func):    @wraps(func)    def wrapper(*args, **kwargs):        try:            return func(*args, **kwargs)        except ValueError as exc:            print(                f"[Business Error] {exc}"            )            raise        except Exception as exc:            print(                f"[System Error] {exc}"            )            raise    return wrapper@handle_exceptiondef execute_agent(prompt):    if not prompt:        raise ValueError("Prompt 不能为空")    return "执行成功"execute_agent("Hello")
```

这里虽然进行了异常分类，但仍然重新抛出异常。

这是因为装饰器不应该擅自将异常转换成正常返回值，否则上层 Agent Runtime 可能无法识别执行失败。

### 应用三：权限验证装饰器

Agent 工具可能涉及不同权限。

例如：

- 普通用户可以搜索知识库。
- 管理员可以修改系统配置。
- 特定用户可以调用高权限工具。

可以通过装饰器进行简单控制。

```
from functools import wrapsdef require_role(required_role):    def decorator(func):        @wraps(func)        def wrapper(user, *args, **kwargs):            if user.get("role") != required_role:                raise PermissionError(                    "没有权限执行该操作"                )            return func(                user,                *args,                **kwargs            )        return wrapper    return decorator@require_role("admin")def delete_knowledge_base(user, kb_id):    print(        f"用户 {user['name']} 删除知识库 {kb_id}"    )admin = {    "name": "Alice",    "role": "admin"}normal_user = {    "name": "Bob",    "role": "user"}delete_knowledge_base(admin, "kb_001")# 会抛出 PermissionError# delete_knowledge_base(normal_user, "kb_001")
```

注意：真实系统中不能仅依赖客户端传入的 `user` 字典判断权限。用户身份必须来自可信的认证上下文，例如经过验证的 JWT、Session 或服务端依赖注入。

### 应用四：Agent 工具注册装饰器

很多 Agent 框架都需要维护工具注册表。

我们可以自己实现一个简化版本。

```
        TOOL_REGISTRY[tool_name] = func        @wraps(func)        def wrapper(*args, **kwargs):            return func(*args, **kwargs)        return wrapper    return decorator@tool(name="search")def search_web(query):    return f"搜索结果: {query}"@tool(name="calculator")def calculate(expression):    return f"计算表达式: {expression}"def execute_tool(name, **kwargs):    func = TOOL_REGISTRY.get(name)    if func is None:        raise ValueError(            f"工具不存在: {name}"        )    return func(**kwargs)if __name__ == "__main__":    print(TOOL_REGISTRY.keys())    print(        execute_tool(            "search",            query="Python Decorator"        )    )
```

输出：

```
dict_keys(['search', 'calculator'])
搜索结果: Python Decorator
```

这个例子体现了装饰器在框架开发中的重要用途：

通过函数定义阶段的装饰器执行注册动作，将函数自动加入框架管理体系。

需要注意，这个示例只展示注册机制，生产级工具注册还需要参数 Schema、类型校验、权限、超时、异步调用支持和工具执行结果标准化。
