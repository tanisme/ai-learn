# 第 01 章：Python 核心基础与高级特性

## 1.3 Python 迭代器与生成器机制

这一节非常重要。对于 AI Agent 工程师来说，迭代器和生成器不仅是 Python 基础知识，更是理解 LLM 流式输出、LangGraph Streaming、FastAPI SSE、异步任务调度和大规模数据处理 的基础。

例如，当你调用一个大模型接口时，模型通常不会等到整个回答生成完毕才返回，而是持续返回 Token：

```
Token 1 → Token 2 → Token 3 → Token 4 → ... → 完整回答
```

如果一次性将所有 Token 加载到内存中，就会增加内存消耗和响应延迟。

生成器允许我们逐个产生数据，而不是一次性构造完整结果。

本节将从 Python 底层迭代协议开始，逐步实现一个支持同步迭代、生成器、异步迭代和 Agent 流式输出的数据处理管道。

## 1.3.1 Iterable 与 Iterator 的区别

首先需要理解两个概念：

- Iterable（可迭代对象）：可以被 `for` 循环遍历的对象。
- Iterator（迭代器）：能够记住当前遍历位置，并逐个返回元素的对象。

它们之间不是同一个概念。

### 1. Iterable：可迭代对象

常见的可迭代对象：

```
# listnumbers = [1, 2, 3]# tuplenames = ("Alice", "Bob", "Charlie")# strtext = "Python"# dictuser = {    "name": "Alice",    "age": 25}# setvalues = {10, 20, 30}for number in numbers:    print(number)
```

这些对象都可以使用 `for` 遍历。

判断对象是否可迭代，可以使用 `collections.abc.Iterable`：

```
from collections.abc import Iterablenumbers = [1, 2, 3]text = "Python"number = 100print(isinstance(numbers, Iterable))print(isinstance(text, Iterable))print(isinstance(number, Iterable))
```

输出：

```
True
True
False
```

为什么 `list` 是 Iterable？

因为它实现了迭代协议，能够通过 `iter()` 返回一个迭代器。

### 2. Iterator：迭代器

迭代器不仅可以遍历，还必须保存当前遍历状态。

```
numbers = [10, 20, 30]iterator = iter(numbers)print(next(iterator))print(next(iterator))print(next(iterator))
```

输出：

```
10
20
30
```

继续调用：

```
print(next(iterator))
```

会出现：

```
StopIteration
```

这表示迭代器中的元素已经全部读取完毕。

迭代器有两个核心特征：

1. 实现 `__iter__()` 方法，返回迭代器自身。
2. 实现 `__next__()` 方法，返回下一个元素；没有元素时抛出 `StopIteration`。

可以通过 `collections.abc.Iterator` 判断：

```
from collections.abc import Iterable, Iteratornumbers = [1, 2, 3]iterator = iter(numbers)print(isinstance(numbers, Iterable))print(isinstance(numbers, Iterator))print(isinstance(iterator, Iterable))print(isinstance(iterator, Iterator))
```

输出：

```
True
False
True
True
```

这里有一个重要结论：

Iterator 本身也是 Iterable，但 Iterable 不一定是 Iterator。

### 3. 两者的核心区别

| 对比             | Iterable        | Iterator                |
| -------------- | --------------- | ----------------------- |
| 中文             | 可迭代对象           | 迭代器                     |
| 是否能使用 for      | 是               | 是                       |
| 是否有 `__iter__` | 是               | 是                       |
| 是否有 `__next__` | 不要求             | 必须                      |
| 是否保存遍历位置       | 不一定             | 是                       |
| 是否通常可以重复遍历     | 通常可以            | 通常不可以                   |
| 典型对象           | list、tuple、dict | list_iterator、generator |

需要特别注意：可迭代对象通常可以重复遍历，但不保证所有 Iterable 都能重复遍历。例如某些文件对象、数据库游标也可能具有一次性消费特征。

### 4. 为什么需要区分？

看下面的例子：

```
numbers = [1, 2, 3]for number in numbers:    print(number)for number in numbers:    print(number)
```

两次遍历都能得到：

```
1
2
3
```

因为 `list` 是可重复遍历的容器。

但迭代器不同：

```
numbers = [1, 2, 3]iterator = iter(numbers)for number in iterator:    print(number)for number in iterator:    print(number)
```

第二次循环不会输出任何内容。

原因是第一次遍历已经消费完了迭代器。

Iterable 与 Iterator 的关系

Iterable

提供创建迭代器的能力

iter(iterable)

Iterator

保存遍历状态，逐个返回元素

next(iterator)

下一个元素

直到 StopIteration

## 1.3.2 `iter()` 和 `next()` 的底层机制

理解了 Iterable 和 Iterator，接下来分析 Python 是如何执行迭代的。

### 1. `iter()` 做了什么？

当执行：

```
numbers = [10, 20, 30]iterator = iter(numbers)
```

Python 会尝试获取对象的迭代器。

从协议层面看，核心相当于：

```
iterator = numbers.__iter__()
```

对于大多数内置容器，Python 会返回一个独立的迭代器对象。

可以验证：

```
numbers = [10, 20, 30]iterator1 = iter(numbers)iterator2 = iter(numbers)print(iterator1 is iterator2)
```

输出：

```
False
```

两个迭代器各自维护自己的遍历位置。

```
numbers = [10, 20, 30]iterator1 = iter(numbers)iterator2 = iter(numbers)print(next(iterator1))print(next(iterator1))print(next(iterator2))
```

输出：

```
10
20
10
```

两个迭代器相互独立。

### 2. `next()` 做了什么？

执行：

```
value = next(iterator)
```

从协议层面相当于：

```
value = iterator.__next__()
```

每次调用都会尝试获取下一个元素。

当没有元素时，抛出：

```
StopIteration
```

可以使用 `next()` 的第二个参数指定默认值：

```
numbers = [10, 20]iterator = iter(numbers)print(next(iterator, None))print(next(iterator, None))print(next(iterator, None))
```

输出：

```
10
20
None
```

这里不会因为迭代结束而抛出异常。

### 3. `for` 循环的底层执行逻辑

这是面试中经常考察的内容。

代码：

```
numbers = [10, 20, 30]for number in numbers:    print(number)
```

可以理解为：

```
numbers = [10, 20, 30]iterator = iter(numbers)while True:    try:        number = next(iterator)    except StopIteration:        break    print(number)
```

两段代码在迭代协议层面的行为是一致的。

因此：

Python 的 `for` 循环本质上就是不断获取迭代器的下一个元素，直到迭代结束。

### 4. 自己实现一个迭代器

我们现在不使用 `list` 的迭代器，而是自己实现迭代协议。

创建文件：

`chapter_01/section_1_3/iterator_demo.py`

```
class NumberIterator:    """    自定义数字迭代器。    从 start 开始，每次增加 step，    最多产生 limit 个数字。    """    def __init__(self, start, limit, step=1):        self.current = start        self.limit = limit        self.step = step        self.count = 0    def __iter__(self):        # 迭代器返回自身        return self    def __next__(self):        # 判断是否结束        if self.count >= self.limit:            raise StopIteration        value = self.current        self.current += self.step        self.count += 1        return valuedef main():    iterator = NumberIterator(        start=10,        limit=5,        step=2    )    for number in iterator:        print(number)if __name__ == "__main__":    main()
```

运行：

```
python iterator_demo.py
```

输出：

```
10
12
14
16
18
```

这个实现已经具备完整的迭代器协议。

不过，这里存在一个值得注意的设计问题：

```
iterator = NumberIterator(10, 5)for x in iterator:    print(x)for x in iterator:    print(x)
```

第二次遍历没有结果。

因为 `NumberIterator` 本身就是迭代器，遍历位置保存在对象自身。

如果希望支持重复遍历，应该将 Iterable 和 Iterator 分开设计。

### 5. 将 Iterable 和 Iterator 分开

创建：

`chapter_01/section_1_3/repeatable_iterator.py`

```
class NumberRangeIterator:class NumberRange:    """    可迭代对象。    自身不保存迭代进度。    每次 iter() 都创建一个新的迭代器。    """    def __init__(self, start, stop, step=1):        if step == 0:            raise ValueError("step 不能为 0")        self.start = start        self.stop = stop        self.step = step    def __iter__(self):        return NumberRangeIterator(            self.start,            self.stop,            self.step        )def main():    numbers = NumberRange(1, 6)    print("第一次遍历：")    for number in numbers:        print(number)    print("第二次遍历：")    for number in numbers:        print(number)    print("两个迭代器独立运行：")    iterator1 = iter(numbers)    iterator2 = iter(numbers)    print(next(iterator1))    print(next(iterator1))    print(next(iterator2))if __name__ == "__main__":    main()
```

输出：

```
第一次遍历：
1
2
3
4
5

第二次遍历：
1
2
3
4
5

两个迭代器独立运行：
1
2
1
```

这种设计方式在工程项目中非常常见：

- Iterable 负责提供数据来源和创建迭代器。
- Iterator 负责维护一次遍历过程中的状态。

### 6. 边界情况：step 为负数

例如：

```
numbers = NumberRange(5, 0, -1)print(list(numbers))
```

输出：

```
[5, 4, 3, 2, 1]
```

如果 `step=0`，则无法推进遍历位置，因此必须拒绝这种配置。

这里还有一个重要的工程原则：

迭代器必须保证每次成功的 `__next__()` 调用都能够推进状态，否则很容易产生无限循环。

## 1.3.3 迭代器协议：`__iter__` 和 `__next__`

前面已经实现过这两个方法，现在进一步分析它们的设计意义。

### 1. `__iter__()` 的职责

```
def __iter__(self):    return self
```

对于迭代器，通常返回自身。

对于普通 Iterable，通常返回一个新的迭代器。

因此，同样叫作 `__iter__()`，具体行为取决于对象扮演的角色。

### 2. `__next__()` 的职责

```
def __next__(self):    if self.finished:        raise StopIteration    value = self.get_next_value()    return value
```

它负责：

1. 判断是否还有数据。
2. 读取当前元素。
3. 推进迭代状态。
4. 返回当前元素。
5. 结束时抛出 `StopIteration`。

注意：`StopIteration` 是正常的迭代结束信号，不应该将它当作一般业务异常处理。

### 3. 模拟数据库分页读取

假设有一个数据库查询接口，每次只读取一页数据，而不是一次性读取所有数据。

我们可以将分页读取封装成迭代器。

创建：

`chapter_01/section_1_3/database_iterator.py`

```
class FakeDatabase:    """    模拟数据库。    """    def __init__(self, records):        self.records = records    def fetch_page(self, offset, page_size):        """        模拟分页查询。        """        return self.records[            offset:offset + page_size        ]class DatabaseIterator:    """    数据库分页迭代器。    每次 next() 最多读取一页，    并逐条返回当前页中的记录。    """    def __init__(self, database, page_size=2):        if page_size <= 0:            raise ValueError("page_size 必须大于 0")        self.database = database        self.page_size = page_size        self.offset = 0        self.buffer = []        self.buffer_index = 0
```

输出：

```
{'id': 1, 'name': 'Alice'}
{'id': 2, 'name': 'Bob'}
{'id': 3, 'name': 'Charlie'}
{'id': 4, 'name': 'David'}
{'id': 5, 'name': 'Eve'}
```

这里的重点不在于模拟数据库，而是理解：

迭代器可以将底层数据读取过程隐藏起来，对外提供统一的逐条读取接口。

实际生产中的数据库分页还需要考虑：

- 排序字段必须稳定，否则分页期间数据变化可能造成重复或遗漏。
- 大数据量场景可以考虑基于主键的 Keyset Pagination。
- 网络异常、数据库断连和重试策略。
- 数据库连接与游标的生命周期。
- 提前终止遍历时如何释放资源。

例如，真正的数据库游标不应该在迭代结束后长期持有连接。可以使用上下文管理器，或者在外层明确管理数据库 Session。

## 1.3.4 生成器函数与 `yield`

接下来进入本节的重点：Generator。

前面实现迭代器需要编写：

- `__iter__()`
- `__next__()`
- 当前遍历状态。
- 结束条件。
- `StopIteration`。

代码相对繁琐。

Python 提供了生成器（Generator），可以更简单地实现相同功能。

### 1. 普通函数与生成器函数

普通函数：

```
def get_numbers():    return [1, 2, 3, 4, 5]numbers = get_numbers()print(numbers)
```

它会直接创建一个列表。

生成器函数：

```
def get_numbers():    yield 1    yield 2    yield 3    yield 4    yield 5numbers = get_numbers()print(numbers)
```

输出类似：

```
<generator object get_numbers at ...>
```

注意：调用生成器函数时，并不会立即执行函数体，而是创建一个生成器对象。

### 2. `yield` 的执行机制

执行：

```
def get_numbers():    print("开始执行")    yield 1    print("继续执行")    yield 2    print("执行结束")generator = get_numbers()print("生成器已经创建")print(next(generator))print(next(generator))
```

输出：

```
生成器已经创建
开始执行
1
继续执行
2
```

这里最重要的是：

当执行到 `yield` 时，函数会暂停，并保留当前执行状态。

下次调用 `next()` 时，从上一次 `yield` 后面继续执行。

生成器执行状态示意

1. 创建生成器

   get_numbers() 创建生成器对象，函数体尚未执行。
2. 第一次 next()

   执行到 yield 1，返回 1，并暂停。
3. 第二次 next()

   从暂停位置继续，执行到 yield 2，返回 2。
4. 第三次 next()

   继续执行到函数末尾，抛出 StopIteration。

### 3. 生成器如何保留局部变量？

看下面的例子：

```
def counter():    count = 0    while count < 3:        count += 1        yield countgenerator = counter()print(next(generator))print(next(generator))print(next(generator))
```

输出：

```
1
2
3
```

为什么局部变量 `count` 没有随着函数暂停而丢失？

因为生成器对象会保存恢复执行所需要的状态，包括：

- 当前执行位置。
- 局部变量状态。
- 相关执行上下文。

可以理解为：生成器将原本一次性执行的函数，变成了一个可以暂停和恢复的计算过程。

### 4. `yield` 与 `return` 的区别

| 对比       | return    | yield |
| -------- | --------- | ----- |
| 返回数据     | 是         | 是     |
| 是否暂停函数   | 否         | 是     |
| 是否保留执行状态 | 不保留后续执行状态 | 保留    |
| 是否可以继续执行 | 不可以       | 可以    |
| 是否用于生成器  | 否         | 是     |

例如：

```
def normal_function():    return 1    return 2def generator_function():    yield 1    yield 2print(normal_function())generator = generator_function()print(next(generator))print(next(generator))
```

输出：

```
1
1
2
```

### 5. 用生成器重写前面的数字迭代器

```
def number_range(start, stop, step=1):    if step == 0:        raise ValueError("step 不能为 0")    current = start    if step > 0:        while current < stop:            yield current            current += step    else:        while current > stop:            yield current            current += stepprint(list(number_range(1, 6)))print(list(number_range(5, 0, -1)))
```

输出：

```
[1, 2, 3, 4, 5]
[5, 4, 3, 2, 1]
```

与手动实现迭代器相比，代码明显简洁。

Python 会自动处理迭代协议和生成器状态管理。

## 1.3.5 `yield from` 与生成器委托

当一个生成器需要遍历另一个可迭代对象时，可以使用 `yield from`。

### 1. 普通写法

```
def child_generator():    yield 1    yield 2    yield 3def parent_generator():    for value in child_generator():        yield valuefor value in parent_generator():    print(value)
```

### 2. 使用 `yield from`

```
def child_generator():    yield 1    yield 2    yield 3def parent_generator():    yield from child_generator()for value in parent_generator():    print(value)
```

两者输出相同：

```
1
2
3
```

`yield from` 不只是语法简写，它还会将子生成器的迭代过程委托给外层生成器。

### 3. 组合多个数据源

```
def source_a():    yield "A1"    yield "A2"def source_b():    yield "B1"    yield "B2"def combined_generator():    yield from source_a()    yield from source_b()for item in combined_generator():    print(item)
```

输出：

```
A1
A2
B1
B2
```

### 4. 在 Agent 中有什么用？

假设一个 Agent 有三个执行阶段：

1. 检索知识库。
2. 调用工具。
3. 生成最终回答。

我们可以将各阶段的流式事件组合起来。

```
def retrieval_events():    yield {"type": "retrieval", "content": "开始检索"}    yield {"type": "retrieval", "content": "检索完成"}def tool_events():    yield {"type": "tool", "content": "调用搜索工具"}    yield {"type": "tool", "content": "工具执行完成"}def llm_events():    yield {"type": "token", "content": "这是"}    yield {"type": "token", "content": "最终回答"}def agent_pipeline():    yield from retrieval_events()    yield from tool_events()    yield from llm_events()for event in agent_pipeline():    print(event)
```

输出：

```
{'type': 'retrieval', 'content': '开始检索'}
{'type': 'retrieval', 'content': '检索完成'}
{'type': 'tool', 'content': '调用搜索工具'}
{'type': 'tool', 'content': '工具执行完成'}
{'type': 'token', 'content': '这是'}
{'type': 'token', 'content': '最终回答'}
```

这就是流式 Agent 管道的一个简化模型。

## 1.3.6 `send()`、`throw()`、`close()`

前面我们一直使用：

```
next(generator)
```

实际上，生成器还支持三种重要操作：

- `send()`：向生成器内部发送数据。
- `throw()`：向生成器内部注入异常。
- `close()`：关闭生成器。

它们是理解协程和生成器控制机制的基础。

### 1. send()：向生成器发送数据

普通 `yield` 可以将数据从生成器传递给外部。

而 `send()` 可以反过来，将外部数据发送给生成器。

示例：

```
def data_processor():    print("生成器启动")    while True:        value = yield        print("收到数据:", value)generator = data_processor()# 启动生成器next(generator)generator.send(100)generator.send(200)generator.send(300)
```

输出：

```
生成器启动
收到数据: 100
收到数据: 200
收到数据: 300
```

这里需要理解一个关键点：

```
value = yield
```

它包含两个方向：

- `yield` 将数据交给外部。
- `send()` 将数据交给 `yield` 表达式，最终赋值给 `value`。

第一次启动时不能直接发送非 `None` 数据：

```
generator = data_processor()generator.send(100)
```

会抛出：

```
TypeError: can't send non-None value to a just-started generator
```

因此通常需要先调用 `next()`，或者使用：

```
generator.send(None)
```

### 2. send() 的双向通信

```
def accumulator():    total = 0    while True:        value = yield total        if value is None:            continue        total += valuegenerator = accumulator()# 启动生成器print(next(generator))print(generator.send(10))print(generator.send(20))print(generator.send(30))
```

输出：

```
0
10
30
60
```

执行流程：

| 操作         | 生成器收到的数据 | 返回给外部 |
| ---------- | -------- | ----- |
| `next()`   | None     | 0     |
| `send(10)` | 10       | 10    |
| `send(20)` | 20       | 30    |
| `send(30)` | 30       | 60    |

这说明生成器不仅可以作为数据生产者，还可以作为一个轻量级的状态处理器。

### 3. throw()：向生成器注入异常

```
def generator():    try:        yield 1        yield 2    except ValueError:        print("生成器内部捕获到 ValueError")    yield 3g = generator()print(next(g))print(g.throw(ValueError("测试异常")))
```

输出：

```
1
生成器内部捕获到 ValueError
3
```

`throw()` 会在生成器暂停的位置注入异常。

如果生成器内部没有捕获该异常，异常就会向外传播。

### 4. close()：关闭生成器

```
def generator():    try:        while True:            yield 1    finally:        print("生成器正在清理资源")g = generator()print(next(g))g.close()
```

输出：

```
1
生成器正在清理资源
```

`close()` 会向生成器注入 `GeneratorExit`，使生成器有机会执行 `finally` 清理逻辑。

对于持有文件、数据库游标等资源的生成器，这一点非常重要。

但要注意：

- `close()` 不等于通用资源管理机制。
- 如果生成器没有被消费完，应确保及时关闭。
- 可以配合 `try/finally` 和上下文管理器管理资源。
- 不要在处理 `GeneratorExit` 时继续 `yield`，否则可能引发 `RuntimeError`。

### 5. 一个资源管理型生成器

```
def read_file(path):    file = open(path, "r", encoding="utf-8")    try:        for line in file:            yield line.rstrip("\n")    finally:        file.close()        print("文件资源已释放")generator = read_file("data.txt")try:    print(next(generator))finally:    generator.close()
```

这里模拟了一个重要的工程场景：

如果调用方只读取第一行就停止了，生成器也必须释放文件资源。

实际项目中，使用 `with open(...)` 通常更加直观：

```
def read_file(path):    with open(path, "r", encoding="utf-8") as file:        for line in file:            yield line.rstrip("\n")
```

当生成器正常结束或被正确关闭时，`with` 会执行资源清理。

## 1.3.7 生成器的惰性求值与内存优化

这是生成器在 Agent 工程中最有价值的能力之一。

### 1. 列表与生成器的区别

列表：

```
def get_numbers():    return [x for x in range(1000000)]numbers = get_numbers()
```

生成器：

```
def get_numbers():    for x in range(1000000):        yield xnumbers = get_numbers()
```

第一种方式会立即构造包含一百万个元素的列表。

第二种方式只创建生成器对象，数据在消费时才逐个产生。

这种机制叫作：

Lazy Evaluation（惰性求值）

### 2. 内存对比

```
import sysnumbers_list = [x for x in range(1000000)]numbers_generator = (    x for x in range(1000000))print(    "列表大小:",    sys.getsizeof(numbers_list))print(    "生成器对象大小:",    sys.getsizeof(numbers_generator))
```

通常可以看到列表占用远大于生成器对象。

不过需要注意：

`sys.getsizeof()` 只统计对象本身的浅层大小，不包括列表中所有对象的完整内存占用，也不能直接代表整个进程的实际内存消耗。

### 3. 生成器为什么节省内存？

列表的执行过程：

```
计算所有数据
    ↓
构造完整列表
    ↓
保存全部元素
    ↓
调用方开始处理
```

生成器的执行过程：

```
创建生成器
    ↓
请求一个元素
    ↓
计算一个元素
    ↓
返回一个元素
    ↓
请求下一个元素
```

生成器通常只需要保存当前计算状态，而不需要保存全部结果。

### 4. 大数据处理示例

假设需要处理一百万条日志。

不推荐：

```
def load_logs(path):    with open(path, "r", encoding="utf-8") as file:        return file.readlines()logs = load_logs("large.log")for line in logs:    process(line)
```

`readlines()` 会将所有行一次性读入内存。

推荐：

```
def load_logs(path):    with open(path, "r", encoding="utf-8") as file:        for line in file:            yield line.rstrip("\n")def process(line):    if "ERROR" in line:        print(line)for line in load_logs("large.log"):    process(line)
```

这使得日志可以逐行处理。

### 5. 生成器不是绝对节省内存

下面的代码虽然使用了生成器，但最终仍然将所有结果放入列表：

```
numbers = list(    x for x in range(1000000))
```

这会重新产生列表级别的内存开销。

另一个容易忽略的问题：

```
def generator():    cache = []    for i in range(1000000):        cache.append(i)        yield i
```

虽然使用了 `yield`，但是 `cache` 仍然保留所有元素。

因此：

是否使用生成器，并不能单独决定内存消耗。关键还在于生成器内部是否保留了大量数据，以及调用方是否将结果全部缓存。

### 6. 生成器在 Agent 数据管道中的应用

假设 Agent 检索到大量文档，需要逐条进行处理。

```
def retrieve_documents():    for i in range(100000):        yield {            "id": i,            "content": f"document content {i}"        }def filter_documents(documents):    for document in documents:        if document["id"] % 2 == 0:            yield documentdef build_context(documents):    for document in documents:        yield {            "id": document["id"],            "context": document["content"]        }documents = retrieve_documents()filtered = filter_documents(documents)contexts = build_context(filtered)for context in contexts:    print(context)    if context["id"] >= 4:        break
```

这里三个函数都采用生成器。

它们形成了一条惰性数据处理管道：

```
retrieve_documents
        ↓
filter_documents
        ↓
build_context
        ↓
Agent
```

只有下游请求数据时，上游才会继续执行。

当下游停止消费时，上游也不会继续生成数据。

这对于大规模 RAG 检索结果处理、文档解析和 Token 流式处理非常有价值。

# 1.3.8 异步迭代器与 Async Generator

前面我们学习了同步迭代器和生成器：

```
for item in iterator:    process(item)
```

现在进入 Python 异步编程中的迭代机制：

```
async for item in async_iterator:    await process(item)
```

这部分是 AI Agent 工程师必须掌握的知识，因为现代 Agent 系统中存在大量异步操作：

- 异步调用大语言模型 API。
- 异步执行多个 Agent 节点。
- 异步读取数据库和向量数据库。
- 异步调用搜索、文件和第三方工具。
- 通过 SSE 向浏览器持续推送模型输出。
- 用户取消请求时，及时停止后台任务。

本节重点是理解：异步生成器不是简单地给普通生成器加上 `async`，而是将迭代过程与事件循环结合起来。

## 一、为什么需要异步迭代器？

先看一个普通生成器：

```
def generate_data():    for i in range(3):        yield i
```

调用：

```
for item in generate_data():    print(item)
```

它可以逐个产生数据，但有一个限制：

如果生成数据之前需要执行网络请求、数据库查询等 I/O 操作，普通生成器本身并不能直接使用 `await`。

例如：

```
import asynciodef generate_data():    for i in range(3):        await asyncio.sleep(1)  # SyntaxError        yield i
```

这是不合法的。

因为 `await` 只能出现在 `async def` 定义的异步函数内部。

我们需要一种能够在迭代过程中执行异步操作的机制。

这就是 Async Iterator 和 Async Generator。

## 二、同步迭代与异步迭代的区别

先对比两种执行方式。

同步迭代：

```
for item in iterator:    process(item)
```

异步迭代：

```
async for item in async_iterator:    await process(item)
```

两者的核心区别：

| 对比         | 同步迭代器                 | 异步迭代器                   |
| ---------- | --------------------- | ----------------------- |
| 获取下一个元素    | `next()`              | `await __anext__()`     |
| 循环语法       | `for`                 | `async for`             |
| 迭代结束       | `StopIteration`       | `StopAsyncIteration`    |
| 核心方法       | `__iter__`、`__next__` | `__aiter__`、`__anext__` |
| 是否支持 await | 不支持直接在迭代协议中等待         | 支持                      |
| 典型场景       | 内存数据遍历                | 网络、数据库、异步流              |

需要特别注意：

异步迭代器的 `__anext__()` 返回的是一个 awaitable 对象，调用者需要通过 `await` 获取结果。

## 三、异步迭代器协议：`__aiter__` 与 `__anext__`

### 1. 实现一个最简单的异步迭代器

创建文件：

`chapter_01/section_1_3/async_iterator_demo.py`

```
import asyncioclass AsyncNumberIterator:    """    自定义异步迭代器。    每次获取数据之前，模拟一次异步 I/O 操作。    """    def __init__(self, start, stop, delay=1):        self.current = start        self.stop = stop        self.delay = delay    def __aiter__(self):        """        返回异步迭代器自身。        Python 3.7+ 中，__aiter__ 应直接返回异步迭代器，        不应该定义为 async def。        """        return self    async def __anext__(self):        """        异步获取下一个元素。        """        if self.current >= self.stop:            raise StopAsyncIteration        # 模拟异步 I/O        await asyncio.sleep(self.delay)        value = self.current        self.current += 1        return valueasync def main():    iterator = AsyncNumberIterator(        start=1,        stop=4,        delay=0.5    )    async for number in iterator:        print("获取数据:", number)if __name__ == "__main__":    asyncio.run(main())
```

运行：

```
python async_iterator_demo.py
```

输出：

```
获取数据: 1
获取数据: 2
获取数据: 3
```

每次获取数据之前，都会执行：

```
await asyncio.sleep(0.5)
```

这模拟了一个异步 I/O 操作。

### 2. `async for` 的底层执行逻辑

代码：

```
async for item in iterator:    print(item)
```

可以从协议层面理解为：

```
async def consume(iterator):    async_iterator = iterator.__aiter__()    while True:        try:            item = await async_iterator.__anext__()        except StopAsyncIteration:            break        print(item)
```

这里有三个核心动作：

1. 调用 `__aiter__()` 获取异步迭代器。
2. 调用 `__anext__()` 获取下一个 awaitable。
3. 使用 `await` 等待结果。

当迭代结束时，抛出 `StopAsyncIteration`。

注意：这是帮助理解的等价执行逻辑，不是 Python 解释器实际生成的源码。

### 3. Python 版本差异

这里有一个容易在面试中被问到的细节。

在较早的 Python 3.5/3.6 迭代协议中，`__aiter__()` 曾经允许返回 awaitable。

从 Python 3.7 开始，`__aiter__()` 应当直接返回异步迭代器。

因此，现在应该这样写：

```
def __aiter__(self):    return self
```

而不是：

```
async def __aiter__(self):    return self
```

后者会返回协程对象，不符合当前异步迭代器协议。

## 四、Async Generator：异步生成器

前面实现异步迭代器时，需要自己编写：

- `__aiter__()`
- `__anext__()`
- `StopAsyncIteration`

和同步迭代器一样，Python 提供了更简单的方式：异步生成器。

### 1. 定义异步生成器

普通生成器：

```
def generate_numbers():    yield 1    yield 2    yield 3
```

异步生成器：

```
async def generate_numbers():    yield 1    yield 2    yield 3
```

注意这里：

```
async def
```

与：

```
yield
```

同时出现。

这样的函数就是异步生成器函数。

调用：

```
generator = generate_numbers()
```

会创建异步生成器对象。

消费时使用：

```
async for number in generator:    print(number)
```

不能直接使用普通 `for` 循环。

### 2. 完整运行示例

创建：

`chapter_01/section_1_3/async_generator_demo.py`

```
import asyncioasync def generate_numbers():    print("异步生成器启动")    for i in range(1, 4):        print("准备生成数据:", i)        await asyncio.sleep(1)        yield i    print("异步生成器结束")async def main():    generator = generate_numbers()    print("生成器已经创建")    async for number in generator:        print("消费数据:", number)if __name__ == "__main__":    asyncio.run(main())
```

输出：

```
生成器已经创建
异步生成器启动
准备生成数据: 1
消费数据: 1
准备生成数据: 2
消费数据: 2
准备生成数据: 3
消费数据: 3
异步生成器结束
```

可以观察到：

```
await asyncio.sleep(1)
```

在每次 `yield` 之前执行。

异步生成器既可以暂停，也可以在恢复执行时等待异步操作。

### 3. 异步生成器的核心优势

假设需要从一个远程接口获取 1000 条数据。

同步方式可能需要阻塞等待：

```
def fetch_data():    for i in range(1000):        time.sleep(0.1)        yield i
```

异步方式：

```
async def fetch_data():    for i in range(1000):        await asyncio.sleep(0.1)        yield i
```

第二种方式在等待期间可以让事件循环调度其他协程。

注意，这里的 `asyncio.sleep()` 只是模拟异步 I/O。实际网络请求需要使用支持异步的 HTTP 客户端，例如 `httpx.AsyncClient` 或 `aiohttp`。

异步并不意味着单个任务执行得更快，而是让任务在等待 I/O 时可以让出执行权。

## 五、同步生成器与异步生成器的完整对比

| 项目         | Generator       | Async Generator       |
| ---------- | --------------- | --------------------- |
| 定义         | `def` + `yield` | `async def` + `yield` |
| 创建对象       | Generator       | Async Generator       |
| 消费方式       | `for`           | `async for`           |
| 获取下一个值     | `next()`        | `await __anext__()`   |
| 是否支持 await | 不支持直接在函数体中使用    | 支持                    |
| 结束异常       | `StopIteration` | `StopAsyncIteration`  |
| 关闭方式       | `close()`       | `aclose()`            |
| 异常注入       | `throw()`       | `athrow()`            |
| 典型场景       | 文件读取、数据处理       | 异步网络流、Agent Streaming |

下面用一张图梳理：

两种生成器的消费流程

同步生成器

`def` + `yield`

`next(generator)`

返回数据 / 暂停

异步生成器

`async def` + `yield`

`await __anext__()`

返回数据 / 暂停 / 等待 I/O

## 六、异步生成器的 `asend()`、`athrow()`、`aclose()`

同步生成器有：

```
generator.send()generator.throw()generator.close()
```

异步生成器也提供相应操作：

```
async_generator.asend()async_generator.athrow()async_generator.aclose()
```

它们都需要配合 `await` 使用。

### 1. asend()：向异步生成器发送数据

```
import asyncioasync def data_processor():    print("处理器启动")    while True:        value = yield        print("收到数据:", value)async def main():    generator = data_processor()    # 启动异步生成器    await generator.asend(None)    await generator.asend(100)    await generator.asend(200)    await generator.asend(300)    await generator.aclose()if __name__ == "__main__":    asyncio.run(main())
```

输出：

```
处理器启动
收到数据: 100
收到数据: 200
收到数据: 300
```

这里的 `asend(None)` 用来启动异步生成器。

### 2. athrow()：注入异常

```
import asyncioasync def generator():    try:        yield 1        yield 2    except ValueError:        print("捕获 ValueError")    yield 3async def main():    g = generator()    print(await g.__anext__())    print(        await g.athrow(            ValueError("测试异常")        )    )asyncio.run(main())
```

输出：

```
1
捕获 ValueError
3
```

### 3. aclose()：关闭异步生成器

```
import asyncioasync def generator():    try:        while True:            yield "data"    finally:        print("执行异步生成器清理逻辑")async def main():    g = generator()    print(await g.__anext__())    await g.aclose()asyncio.run(main())
```

输出：

```
data
执行异步生成器清理逻辑
```

实际工程中，异步生成器可能持有：

- HTTP 流式响应。
- 数据库游标。
- WebSocket 连接。
- 文件句柄。
- 后台任务。

因此必须重视异步生成器的关闭和资源释放。

## 七、异步生成器与并发执行

这里是一个重要的进阶问题：

使用 `async for` 是否意味着多个数据项会并发处理？

答案：不会。

看下面的代码：

```
import asyncioasync def generate_data():    for i in range(3):        await asyncio.sleep(1)        yield iasync def process(item):    await asyncio.sleep(1)    print("处理完成:", item)async def main():    async for item in generate_data():        await process(item)asyncio.run(main())
```

整体执行时间大约为 6 秒：

- 生成一个数据：1 秒。
- 处理一个数据：1 秒。
- 一共三个数据。

因为生成和处理是顺序执行的。

### 1. 使用 asyncio.gather 并发处理

如果三个数据之间没有依赖关系，可以考虑并发处理：

```
import asyncioasync def generate_data():    for i in range(3):        await asyncio.sleep(1)        yield iasync def process(item):    await asyncio.sleep(1)    print("处理完成:", item)async def main():    tasks = []    async for item in generate_data():        tasks.append(            asyncio.create_task(                process(item)            )        )    await asyncio.gather(*tasks)asyncio.run(main())
```

这里三个处理任务可以并发运行。

但是，这种方式有一个问题：

```
tasks.append(asyncio.create_task(...))
```

如果数据量达到一百万，程序可能创建一百万个 Task，造成内存压力。

### 2. 使用 Semaphore 限制并发量

更合理的方式是限制同时运行的任务数量。

```
import asyncioasync def generate_data():    for i in range(20):        yield iasync def process(item, semaphore):    async with semaphore:        await asyncio.sleep(1)        print("处理完成:", item)async def main():    semaphore = asyncio.Semaphore(5)    tasks = []    async for item in generate_data():        task = asyncio.create_task(            process(item, semaphore)        )        tasks.append(task)    await asyncio.gather(*tasks)asyncio.run(main())
```

这里最多只有 5 个 `process()` 协程同时进入受限区域。

但要注意：虽然限制了实际并发执行数量，`tasks` 仍然会保存全部任务。

所以对于真正的大规模数据处理，还需要采用有界队列和固定数量的 Worker，而不是无上限创建 Task。

# 1.3.9 生成器在 SSE 和 LLM Streaming 中的应用

这一节直接关联 Agent 工程实践。

你之前学习过 FastAPI、SSE 和 LangGraph Streaming，现在将这些知识与生成器机制结合起来。

## 一、为什么 LLM 需要流式输出？

假设用户向 Agent 提问：

```
请分析 LangGraph 的执行机制。
```

如果采用普通响应方式：

```
用户请求
   ↓
Agent 执行
   ↓
调用 LLM
   ↓
等待完整回答
   ↓
一次性返回
```

假设模型生成需要 10 秒，用户可能需要等待 10 秒才看到第一个字。

而采用流式响应：

```
用户请求
   ↓
Agent 执行
   ↓
LLM 开始生成
   ↓
Token 1 → Token 2 → Token 3
   ↓
持续推送给浏览器
```

用户可以在生成过程中看到内容。

这通常能显著改善首 Token 延迟（TTFT，Time To First Token）和交互体验，但总生成时间不一定缩短。

## 二、SSE 的基本工作原理

SSE 全称：

Server-Sent Events

它是一种基于 HTTP 的服务器向客户端单向推送机制。

基本结构：

```
Browser
   |
   | HTTP Request
   v
FastAPI
   |
   | StreamingResponse
   v
Async Generator
   |
   | yield event
   v
SSE Stream
   |
   v
Browser EventSource
```

SSE 事件通常采用这样的文本格式：

```
event: token
data: {"content":"Hello"}

event: token
data: {"content":" World"}

event: done
data: {}
```

每个事件以空行作为结束标记。

注意，SSE 本身不负责模型推理。它只是服务器向客户端传输事件的协议。

## 三、使用 FastAPI 实现 SSE

我们先实现一个完全独立、可运行的项目，不依赖 LangChain 或真实模型。

项目结构：

```
chapter_01/
└── section_1_3/
    └── sse_demo/
        ├── app.py
        └── requirements.txt
```

### 1. 安装依赖

`requirements.txt`

### 五、生产环境中的 SSE 事件模型

不建议生产项目只发送裸 Token。

Agent 还需要告诉前端：

- 当前执行到了哪个节点。
- 是否正在调用工具。
- 工具是否执行成功。
- 是否出现错误。
- 是否需要用户确认。
- 是否已经生成最终答案。

可以定义统一事件模型：

```
from dataclasses import dataclassfrom typing import Any, Dictimport json@dataclassclass AgentEvent:    event: str    data: Dict[str, Any]    def to_sse(self):        payload = json.dumps(            self.data,            ensure_ascii=False        )        return (            f"event: {self.event}\n"            f"data: {payload}\n\n"        )
```

使用：

```
event = AgentEvent(    event="tool_start",    data={        "tool": "web_search",        "status": "running"    })print(event.to_sse())
```

输出：

```
event: tool_start
data: {"tool": "web_search", "status": "running"}
```

建议在 Agent 项目中统一以下事件类型：

| 事件           | 含义         |
| ------------ | ---------- |
| `run_start`  | Agent 开始执行 |
| `node_start` | 节点开始执行     |
| `node_end`   | 节点执行完成     |
| `tool_start` | 工具调用开始     |
| `tool_end`   | 工具调用完成     |
| `token`      | 模型输出 Token |
| `interrupt`  | 等待人工确认     |
| `error`      | 执行错误       |
| `done`       | 整个任务结束     |

这与 LangGraph 的节点执行事件、消息流事件和状态更新事件可以建立映射关系。

## 二、定义 Agent 事件模型

`app/events.py`

```
from dataclasses import dataclassfrom typing import Any, Dictimport json@dataclassclass AgentEvent:    """    Agent 统一事件模型。    所有执行节点、工具调用、模型 Token    都通过统一的事件结构向外传递。    """    event: str    data: Dict[str, Any]    def to_sse(self) -> str:        """        转换为 SSE 格式。        """        payload = json.dumps(            self.data,            ensure_ascii=False        )        return (            f"event: {self.event}\n"            f"data: {payload}\n\n"        )    def to_dict(self) -> Dict[str, Any]:        """        转换为普通字典。        """        return {            "event": self.event,            "data": self.data        }
```

这里使用 `dataclass`，主要是为了减少事件对象的样板代码。

## 三、实现异步 Token 生成器

`app/generators.py`

```
import asynciofrom typing import AsyncIteratorasync def generate_tokens(    text: str,    delay: float = 0.1) -> AsyncIterator[str]:    """    模拟 LLM Token 流式生成。    这里按照空格切分文本，模拟 Token。    真实项目中应该使用 LLM 的 astream()。    """    if delay < 0:        raise ValueError("delay 不能小于 0")    tokens = text.split(" ")    for index, token in enumerate(tokens):        await asyncio.sleep(delay)        # 保留原始空格        if index < len(tokens) - 1:            token += " "        yield token
```

这里的返回类型：

```
AsyncIterator[str]
```

表示这是一个异步迭代器，能够逐个产生字符串。

## 八、这个教学项目距离生产环境还差什么？

上面的项目已经串起了异步生成器、Agent 事件和 SSE，但真正生产部署还需要进一步完善。

| 问题    | 教学项目     | 生产环境建议               |
| ----- | -------- | -------------------- |
| 请求方式  | GET 参数   | 通常使用 POST 创建运行任务     |
| 身份验证  | 无        | 用户认证与授权              |
| 任务标识  | 无        | `run_id`、`thread_id` |
| 事件顺序  | 单生成器顺序输出 | 事件序号与持久化             |
| 取消机制  | 依赖请求取消   | 显式取消与任务清理            |
| 错误处理  | 简单捕获     | 结构化错误码和重试策略          |
| 心跳    | 无        | SSE heartbeat        |
| 断线恢复  | 不支持      | Last-Event-ID 或事件游标  |
| 状态持久化 | 无        | Checkpoint / 数据库     |
| 并发控制  | 无        | 限流、队列和背压             |
| 监控    | 无        | 日志、Tracing、Metrics   |

尤其需要注意三个工程问题：

1\. 客户端断开不代表所有后台工作都自动停止。

需要明确任务与连接的生命周期关系。连接断开后，如果任务只服务于当前请求，可以取消并清理；如果任务需要继续执行，则应该将它与 HTTP 连接解耦。

2\. 不能无限缓存 Token 或任务。

生成器可以减少中间结果缓存，但如果消费者速度跟不上生产者，仍然需要背压机制，例如有界 `asyncio.Queue`。

3\. SSE 不等于完整 Agent 状态管理。

SSE 只负责传输事件。Agent 的执行状态、Checkpoint、Interrupt、Resume 应由独立的 Runtime 或工作流引擎负责。

# 九、1.3 面试重点总结

下面这些问题建议重点掌握。

| 面试问题                       | 核心答案                                                         |
| -------------------------- | ------------------------------------------------------------ |
| Iterable 和 Iterator 有什么区别？ | Iterable 可以创建迭代器；Iterator 保存遍历状态并实现 `__next__`。              |
| `for` 循环的底层原理是什么？          | 通过迭代协议持续获取元素，直到结束。                                           |
| Generator 和普通函数有什么区别？      | Generator 使用 `yield` 暂停并保存执行状态。                              |
| `yield` 和 `return` 有什么区别？  | `yield` 可以暂停并恢复，`return` 结束函数。                               |
| `yield from` 有什么作用？        | 委托子迭代器或生成器处理数据，并转发相关控制。                                      |
| `send()` 有什么作用？            | 向暂停的生成器发送数据。                                                 |
| `throw()` 有什么作用？           | 在生成器暂停位置注入异常。                                                |
| `close()` 有什么作用？           | 通过 `GeneratorExit` 关闭生成器。                                    |
| 为什么生成器节省内存？                | 通常逐个产生元素，不需要保存完整结果。                                          |
| 异步迭代器与同步迭代器有什么区别？          | 异步迭代器通过 `await __anext__()` 获取元素。                            |
| `async for` 的底层机制是什么？      | 调用 `__aiter__()`，反复等待 `__anext__()`，直到 `StopAsyncIteration`。 |
| Async Generator 有什么优势？     | 可以在逐个产生数据的过程中执行异步 I/O。                                       |
| `async for` 会自动并发吗？        | 不会，循环体仍然按顺序执行。                                               |
| SSE 与生成器有什么关系？             | 异步生成器可以持续产生事件，由 StreamingResponse 逐步发送。                      |
| Agent Streaming 如何处理取消？    | 捕获 `CancelledError` 执行必要清理后重新抛出。                             |
